# Security and Confidentiality

This repository is intended for public professional presentation.

## Do not publish

- API keys, access tokens, passwords, private keys, or environment files
- Database connection strings or production configuration
- Private source code or proprietary business rules
- Customer, supplier, employee, or other personal data
- Payment-provider secrets, webhook secrets, or privileged server credentials
- Private architecture diagrams, deployment details, or non-public product roadmaps
- Screenshots that expose private dashboards, identifiers, or account details

## Before adding any example

1. Confirm that you own it or have permission to publish it.
2. Build it separately from private production repositories.
3. Use synthetic data and mock services.
4. Search the files and Git history for secrets before publishing.
5. Check screenshots and documentation for private details.
6. Keep private repositories private; never assume that deleting a file from the latest commit removes it from Git history.

If a security issue is discovered in a public demo, avoid posting secrets or personal data in a public issue. Contact the repository owner privately.
